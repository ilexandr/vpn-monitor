## Живая проверка на рабочем компьютере

До исправления: служба Running, handshake = 0, rx_bytes = 0, маршрут к Endpoint выбирал другой активный VPN. Временный адресный маршрут через физическую сеть восстановил API; остальные VPN не останавливались.

Затем установлен проверяемый движок с защищённой политикой для выбранного профиля. Движок самостоятельно создал маршруты основного и резервного Endpoint через физическую сеть. Первые попытки имитации сбоя правилом firewall и изменением маршрута не нарушили уже работающую связь и не считаются подтверждением переключения.

Для воспроизводимого отказа только активная защищённая копия профиля временно получила заведомо недоступный Endpoint из тестовой сети. Исходный выбранный профиль, ключи и его сохранённая копия не менялись. При первом запуске обнаружен отказ из-за полной переустановки адресов работающего интерфейса; исправление заменяет её на добавление только отсутствующих адресов/маршрутов и не отправляет такую ошибку как фатальную ошибку watcher.

Повторный тест с итоговым движком прошёл:

- установлен отказ основного подключения, собственный handshake отсутствует;
- контроллер сам переключил существующего Peer на резерв; получены новый собственный handshake и подтверждённая связь;
- ручная остановка соблюдена: служба оставалась остановленной в контрольном интервале;
- собственные временные маршруты удалены при остановке;
- исходная активная копия восстановлена; после обычного запуска связь вернулась через основной Endpoint;
- тестовые firewall/маршруты удалены, политика с реальным резервом сохранена для выбранного профиля; автоматический возврат к основному выключен.
