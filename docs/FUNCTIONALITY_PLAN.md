# Предложения следующего этапа

Все четыре пункта утверждены пользователем для общего релиза 0.1.71 и реализованы. Ниже сохранено описание состава пакета.

1. **Инциденты и время недоступности.** Объединять связанные события API, туннеля и клиентов в инцидент с началом, окончанием и длительностью. Показывать вероятный уровень проблемы: общий VPN, сервер мониторинга или отдельный клиент. Основываться на имеющихся проверках, сохранять неизвестное состояние отдельно от подтверждённой недоступности. Начать с текущего аккаунта и существующего срока хранения истории.
2. **Профили проверок для групп и клиентов.** Проверять нужные сервисы: RDP, SMB, Radmin или заданные TCP-порты. Наследовать профиль группы с переопределением клиента; дать бюджет параллельности и частоты, чтобы не увеличить нагрузку незаметно. Отдельно показывать доступность компьютера и конкретного сервиса.
3. **Правила уведомлений и обслуживание.** Задержка перед тревогой, расписание тишины, временное отключение уведомлений выбранной группы и объединение массовых событий. Остановка общего туннеля не должна превращаться в поток уведомлений о каждом клиенте. Объяснять в интерфейсе, почему событие было подавлено.
4. **Сохранённые представления списка.** Сочетания поиска, группы, фильтра, сортировки и колонок: например, «Кассы», «Серверы», «Проблемные». Сохранять на пользователя Windows; при смене API-аккаунта не раскрывать имена недоступных клиентов. Быстрые представления помогут удержать главное окно компактным при росте сети.

В 0.1.71 пункты объединены в окно «Мониторинг»; сохранённые представления также доступны из меню «Ещё». TCP-проверки включаются явно, с бюджетом запросов и параллельности.

Частичные обновления остаются отложенными. В 0.1.73 добавлен единый контроль соединения внутри службы: он переподключает движок общего туннеля при подтверждённом сбое, с задержкой и ограничением частоты; ручная остановка службы не отменяется.


## Следующие этапы (25.10.2026)

- **Настройки профилей AWG и резервный Endpoint — реализовано в 0.1.73.** В интерфейсе профиля задавать основной и резервный адрес сервера, порт, приоритет и политику переключения. Предпочтительно хранить один профиль с двумя Endpoint: ключи и маршруты не дублируются. В настройках — время подтверждения потери связи, число неудачных проверок, интервал проверки, минимальное время между переключениями, автоматический возврат к основному или работа на резервном до следующего сбоя. Проверять связь через туннель и доступность API/контрольного адреса, а не только ICMP внешнего IP. Предусмотреть состояния «основной», «ожидание», «резервный», причину и историю переключений, защиту от бесконечных переключений и ручное управление. Изменения общего туннеля — через привилегированную службу, единая политика для всех Windows/RDP-сеансов; приложение пользователя не должно самостоятельно перезапускать общую службу. Отдельно проверить обновление Endpoint без разрыва через движок AWG; если оно недоступно — управляемое переподключение. Секреты остаются в защищённом хранилище. В менеджере добавлено окно «Связь и резерв…» для выбранного профиля. Основной Endpoint берётся из профиля, резервный задаётся отдельно; автоматический возврат выключен по умолчанию. Реализованы контрольный IPv4/TCP, ICMP, учёт входящего трафика, подтверждение потери, пауза между попытками и не более трёх переподключений за десять минут. Для профиля без подходящего IPv4 требуется явный контрольный адрес. Переключение на резерв поддержано для одного Peer. Полный редактор остальных параметров профиля реализован в 0.1.74: маски ключей, проверка движком, DPAPI, защита от одновременного редактирования.
- **Переименование проекта.** Пользователь хочет отразить связь с WGDashboard; предварительный вариант — awgdashmon. Перед переименованием предложить несколько близких и самостоятельных названий и согласовать выбор. Составить план совместимости: GitHub и адрес обновлений, идентификатор установщика, службы, каталоги профилей/настроек, ярлыки и миграция существующих установок. Не менять идентификаторы и URL без переходного периода. Пользователь выбрал **AWG Dash Monitor**. В 0.1.74 изменено отображаемое имя и ярлыки; служебные идентификаторы и GitHub URL сохранены. См. RENAME_COMPATIBILITY.md.

- **Частичные обновления, этап 1 — 0.1.74.** Файловый манифест релиза (размеры/SHA-256), локальный расчёт отличий, проверка безопасных путей и повреждённых файлов. Загрузка по отдельным файлам ещё не включена. Далее: доверенный манифест из закреплённого GitHub Release, файловые пакеты, транзакция/откат и совместимость всех RDP-сеансов; полный установщик остаётся резервным вариантом.
- **Следующий пакет.** Подтверждённая история переключений Endpoint в менеджере; управляемая ручная проверка резервного туннеля с возвратом; продолжение частичных обновлений. Пользователь подтвердил реальный переход на резерв при неверном основном Endpoint (25.10.2026). Проверка системных уведомлений остаётся открытой.


## Пакет 0.1.75
- Подтверждённая история переключений в менеджере: 200 событий, защищённое хранилище, сохранение между запусками.
- Ручная проверка резерва силами службы с таймаутом, проверкой возврата, общим бюджетом и защитой межсеансовых команд. Только с исправного основного, после подтверждения; профиль не переписывается.
- Частичные обновления, этап 2: получение и проверка манифеста GitHub из интерфейса, сравнение с установленными файлами и оценка объёма без сжатия. Не установка отдельных файлов.

Следующие этапы: файловые пакеты с транзакционным применением/откатом и совместимостью RDP-сеансов; сохранение рабочего Endpoint при обновлении/перезапуске по выбранной политике; понятное объяснение недоступности ручной проверки и история результатов по профилям. Живую ручную проверку новой команды выполнить после возвращения корректного основного Endpoint.


## Управление пользователями — 26.10.2026

По просьбе пользователя приоритет перенесён на сервер. В Web реализованы список/создание/смена пароля/блокировка/удаление обычных аккаунтов для admin. Существующие ограничения по группам сохранены, master-admin защищён. Изменения установлены и проверены на рабочем сервере; данные и backup сохранены. Проверки: WEB_USER_MANAGEMENT_VERIFICATION.md.

Реализовано в 0.1.76: управление теми же пользователями из Windows-программы через подготовленный admin API, без отдельной базы и дублирования правил доступа. Проверены реальные операции на временном аккаунте, разграничение прав и удаление тестовых данных.

## Автозапуск туннеля — 29.10.2026, 0.1.77

Исправлен ручной тип запуска службы: одноразовая миграция настроенного туннеля на Automatic (Delayed), режим виден и изменяется в менеджере. Настройка общая для всех сеансов, сохраняется при обновлении/переустановке; ручной Stop не отменяется мониторингом. SCM выполняет две ограниченные попытки восстановления после ошибки. Удаление выбранного профиля отключает автозапуск. Локальные настройки применены и проверены без разрыва соединения; запуск после настоящей перезагрузки обоих компьютеров проверяет пользователь.

## Прокси и трей — 29.10.2026, 0.1.78

Режим HTTP-запросов задаётся явно: direct по умолчанию либо HTTP-прокси без авторизации. Обновления и elevated helper используют одинаковую политику, API сервера — по отдельному opt-in. Системный прокси не наследуется, изменения применяются без перезапуска. Добавлены сохранение/импорт/экспорт и проверки адреса. В трее пункт обновления списка заменён на «О программе…». Пользователь подтвердил работу управления пользователями; исправление автозапуска 0.1.77 ожидает проверки после настоящей перезагрузки.
