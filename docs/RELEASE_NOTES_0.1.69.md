# VPN Monitor 0.1.69

Исправления окон, устойчивость подключения и защита настроек объединены в один релиз.

## Окна

- Настройки, журнал, диагностика и остальные дочерние окна используют единое поведение владельца: отдельные кнопки на панели задач не создаются, после закрытия активного окна фокус возвращается его владельцу.
- Вложенные окна настроек возвращают фокус последовательно. Намеренно скрытое/свёрнутое главное окно не раскрывается; при завершении приложения возврат фокуса отключён.
- Значок трея загружается по явному адресу ресурса сборки клиента.

## Подключение и журнал

- На проверенном сервере Uvicorn keep-alive составляет 5 секунд, как и обычный интервал опроса. Это вероятная причина части кратковременных сбросов HTTP; перезапусков службы и предупреждений в её журнале не обнаружено. Серверные службы и туннель не изменялись.
- Срок простоя соединений в клиентском пуле — 3 секунды. При сбросе/оборванном HTTP-ответе GET повторяется один раз с короткой задержкой в общем бюджете 12 секунд. HTTP 401/403 и другие ответы сервера немедленно не повторяются.
- Причины отказа различаются: DNS, отказ подключения, сброс, недоступная сеть, таймаут, HTTP-код или некорректный JSON. Последний успешный список сохраняется.
- Одинаковая непрерывная ошибка подробно записывается при первом появлении и затем не чаще раза в 5 минут. Смена причины фиксируется сразу; восстановление — отдельной записью. Это не скрывает состояние ошибки в интерфейсе.
- В диагностике видны число неудачных циклов подряд, число повторов GET и время восстановления связи. При смене подключения показатели сбрасываются.
- Завершение клиента при ожидающем API-ответе не создаёт ложный таймаут и не освобождает уже уничтоженный семафор.

## Настройки и уведомления

- Настройки сохраняются атомарно. `settings.previous.json` содержит предыдущий исправный снимок; повреждение основного файла позволяет загрузить эту копию, включая пароль, защищённый DPAPI. Повреждённый файл не заменяет хорошую резервную копию.
- В разделе уведомлений есть «Проверить уведомление Windows»: отправляет одно тестовое сообщение, не меняя статусы клиентов или туннеля. Подтвердить фактическое отображение может пользователь — Windows может подавлять сообщение своими настройками.

## Изоляция проверок

- Журнал проверок: `artifacts/regression/logs`, настройки: `artifacts/regression/settings`.
- Ресурсное приложение проверок не запускает рабочий клиент, таймеры и автозапуск. Новые тестовые записи не попадают в пользовательский `client.log` и не заменяют его настройки.
- Старые записи `127.0.0.1`, намеренных HTTP 503/таймаутов и часть ошибок загрузки значка в прежних журналах относятся к проверкам до исправления изоляции; они остаются историческими записями.

## Что проверить

1. Открыть/закрыть журнал; пройти «Настройки → Пользовательские действия», закрыть вложенные окна и настройки. Главное окно должно оставаться доступным поверх прежних окон, без отдельного восстановления с панели задач.
2. Обычные сворачивание и закрытие в трей должны работать как раньше. Закрытие фонового дочернего окна не должно раскрывать намеренно скрытое главное окно.
3. В диагностике посмотреть счётчики ошибок/повторов и время восстановления. При реальной потере связи статус должен оставаться неизвестным, список — сохраняться; после возврата связи показатели должны обновиться.
4. «Настройки → Уведомления → Проверить уведомление Windows». Проверить отображение сообщения в своём сеансе.

Проверены настоящий TCP-сброс с восстановлением, отсутствие немедленного повтора 401, ограничение повторяющихся записей, закрытие при ожидающем ответе, фокус/вложенные окна, изоляция тестов и восстановление повреждённых настроек. Реальные параллельные RDP-сеансы остаются отдельной проверкой.
