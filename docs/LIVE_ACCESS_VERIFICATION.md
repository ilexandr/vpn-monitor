# Ограниченный доступ — проверка 24 октября 2026

Проверка выполнена с рабочим Debian-сервером VPN Monitor и клиентским кодом 0.1.69. Пользователь подтвердил работу релиза 0.1.69. Исправлений приложения по результатам этой проверки не потребовалось; новый установщик не выпускался.

## Что проверено

- Временно создан ограниченный аккаунт для существующей непустой группы, в которой находится только часть клиентов сервера. Уже существующие аккаунты не изменялись.
- `/api/v1/me` возвращает ограниченную роль и нужную группу.
- Web (`/api/status`) и Desktop (`/api/v1/peers`) возвращают одинаковые разрешённые идентификаторы клиентов; `/api/v1/groups` и Web возвращают только разрешённую группу.
- Имена других групп не попадают в поле групп разрешённых клиентов. Итоговое количество совпадает с `/api/v1/summary`.
- Страница Web доступна с разрешённой авторизацией. Прямой запрос разрешённого клиента успешен, чужого — HTTP 404.
- Настоящий `MainViewModel` сначала загрузил административный список, затем переключился на ограниченный аккаунт: прежний список и группы очистились сразу, после загрузки основная коллекция и WPF-представление содержали только разрешённые данные.
- Второй временный аккаунт без соответствующей группы получил пустой список в Web и Desktop. Неверный пароль возвращает HTTP 401; Desktop показывает ошибку и не сохраняет данные предыдущего аккаунта после смены авторизации.

Временные аккаунты удалены в блоке `finally`; исходное содержимое файла пользователей, владелец/группа и права восстановлены. Удалённые учётные данные повторно проверены: HTTP 401. Служба сервера не перезапускалась, настройки рабочего Desktop и VPN-туннель не изменялись.

Это проверка реального серверного ограничения и клиентской модели/представления WPF. Визуальная работа Web в браузере и настоящие одновременные RDP-сеансы этим тестом не проверяются.

## Повторная проверка Desktop

В `RegressionChecks` добавлен явный режим `--live-access`. Обычный запуск проверок не обращается к рабочему серверу. Перед запуском этого режима оператор должен подготовить временные аккаунты и гарантировать их удаление после завершения.

Режим читает одну строку JSON из стандартного ввода с полями:

- `ServerUrl` — адрес тестируемого API;
- `AdminUsername`, `AdminPassword` — административные учётные данные;
- `Username`, `Password` — временный ограниченный аккаунт с существующей группой;
- `EmptyUsername`, `EmptyPassword` — временный аккаунт без соответствующей группы;
- `ExpectedPeerIds` — массив разрешённых идентификаторов из проверенного Web-снимка.

Запуск: `dotnet RegressionChecks/bin/Release/net8.0-windows/RegressionChecks.dll --live-access` после сборки Release. Учётные данные следует передавать из памяти через перенаправленный stdin, а не аргументы командной строки или файлы репозитория. Режим сам не создаёт и не удаляет аккаунты, не сохраняет настройки и не печатает учётные данные. Его настройки и журналы используют изолированные каталоги `artifacts/regression`.
