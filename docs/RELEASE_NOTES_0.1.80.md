# AWG Dash Monitor 0.1.80

- Служба запоминает последний подтверждённый входящим трафиком Endpoint отдельно для каждого профиля. При следующем запуске или обновлении она может сразу использовать ранее работавший резерв; текущее соединение проверяется заново. Конфигурация профиля и его основной Endpoint не переписываются.
- В «Связь и резерв…» добавлена настройка «После перезапуска начинать с последнего подтверждённого Endpoint» (по умолчанию включена). Она работает при включённом контроле соединения. Отключение очищает сохранённый выбор. Если включён автоматический возврат к основному, после запуска с резерва действует обычный интервал возврата.
- Сохранённый выбор связан с ID и точной конфигурацией профиля, а также основным/резервным адресами. Изменение ключей, маршрутов, параметров или адресов не позволяет применить старую запись. Повреждённая запись игнорируется. Сохранённый резерв выбирается до разрешения DNS основного адреса.
- Временная ручная проверка резерва не меняет запомненный адрес. Остановка службы остаётся остановкой; сохранение Endpoint не запускает службу самостоятельно.
- История теперь содержит профиль события. У каждого профиля сохраняются свои последние 200 событий, а «Все профили» показывает общую ленту из 200. При открытии из менеджера выбран профиль из списка; доступен переключатель. Старые записи остаются в «Без привязки к профилю» и не приписываются задним числом.
- Длинные описания событий переносятся по строкам; в истории видна попытка возобновления с сохранённого резерва без ложного утверждения, что связь уже установлена.

При первом переходе со старого движка подтверждённого сохранённого Endpoint ещё нет: он появится после работы версии 0.1.80. История по профилям также начинает накапливаться с нового движка; прежняя общая история сохраняется.

Проверить после обновления:
1. В менеджере открыть «История связи…», переключить профили, общую ленту и старые записи без привязки.
2. Когда версия 0.1.80 подтвердит работу через резерв, в удобный момент отключить/подключить туннель без изменения конфигурации. В истории должна появиться запись выбора сохранённого резерва, затем подтверждение связи. Намеренно портить рабочий профиль для этой проверки не обязательно.
3. Если разрешён возврат к основному, проверить его после заданного интервала. Отключённая настройка запоминания должна оставлять обычный запуск с основного.
