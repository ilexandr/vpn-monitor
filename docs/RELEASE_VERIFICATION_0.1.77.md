# Проверка 0.1.77 — 29.10.2026

Причина: установленная служба имела Start=3 (Demand), DelayedAutoStart отсутствовал; в установщике New-Service -StartupType Manual. Пользователь подтвердил проблему на обоих компьютерах. Локальный туннель уже был подключён вручную и оставлен работающим.

- Клиент/менеджер/RegressionChecks собраны без ошибок и предупреждений. Полный набор: 42 PASS; после расширения сохранения политики при переустановке целевой StartupChecks повторён успешно.
- Проверены одноразовая миграция существующего профиля, сохранение явного Manual при обновлении, восстановление Automatic/Manual при переустановке, отсутствие профиля, явно Disabled, отказ проверки профиля и SCM, отсутствие ложного маркера успеха.
- WPF: отображение режима SCM, обновление после изменения в другом сеансе, блокировка кнопки во время операции, невозможность включить без выбранного профиля; обе темы при узком окне проверены визуально.
- На настоящей локальной службе новым Manager CLI выполнена миграция: Start=2, DelayedAutoStart=1; ConfigureRecovery проверен через sc qfailure/qfailureflag: restart через 30000/60000 мс, затем отсутствие действия, reset=86400, обработка non-crash failures включена.
- Реальные переключения Manual → startup-setup existing → Automatic подтвердили очистку delayed-флага, сохранение ручного режима при обновлении и восстановление отложенного автозапуска. Режим Automatic оставлен включённым. Состояние службы Running и PID не менялись; connection.json показывал Healthy/Connected.
- Выход службы по ручной остановке успешный (host/engine), поэтому SCM failure recovery не запускает её заново. Аварийный краш рабочего туннеля искусственно не вызывался.
- Реальная перезагрузка локального компьютера и удалённого Windows-сервера в ходе разработки не выполнялась; это оставлено пользовательской проверкой после установки.
