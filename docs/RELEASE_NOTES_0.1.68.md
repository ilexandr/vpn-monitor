# VPN Monitor 0.1.68

Диагностика, отчёты и журналы объединены в один релиз.

## Диагностика и ZIP

- «О программе → Диагностика и отчёт…» или «Журнал → Диагностика…».
- Сводка содержит версии приложения/.NET/Windows, архитектуру, права процесса и номер сеанса; состояние API, время попытки и последнего успешного ответа; состояние общей службы AWG, доступности VPN и наличия выбранного профиля.
- Режим API и времена успешных запросов сбрасываются при смене подключения. Обновление сводки читает текущее состояние приложения; дополнительных сетевых запросов не выполняет.
- Сводку можно скопировать или сохранить локальный ZIP. Текущий и предыдущий журналы добавляются только при включённой галочке, до 512 КБ каждого. Архив создаётся в фоне; отмена или ошибка не заменяет ранее сохранённый файл частичным архивом.
- Маскируются известный пароль подключения, типовые поля паролей/токенов/ключей, заголовки Basic/Bearer, учётные данные и параметры URL, пути профиля пользователя Windows. Адрес сервера и сведения о системе остаются. Отчёт не является анонимным; содержимое можно просмотреть перед самостоятельной отправкой.
- Настройки, конфигурации VPN, DPAPI-архивы и история клиентов не собираются. Автоматической отправки нет.

## Последнее обновление

- Из общедоступной записи показываются фаза, дата и сообщение последнего обновления компьютера, а также идентификатор и путь подробных журналов для администратора.
- Читаются только небольшие записи с ожидаемым именем и известной фазой. Повреждённая запись пропускается. Сохранённая промежуточная фаза не объявляется работающим процессом обновления.
- Диагностика не читает закрытый каталог обновления и не запрашивает повышение прав.

## Журналы

- Текущий `client.log` и три архива `.1`–`.3`, до 2 МБ каждый. Слишком большая отдельная запись сокращается. При первой ротации ограничивается и размер старого большого журнала.
- Запись согласуется между процессами одного пользователя Windows через локальный файл блокировки. Ожидание блокировки ограничено; ошибка журналирования не завершает приложение.
- В просмотрщике можно выбрать текущий журнал или архив, открыть папку и перейти к диагностике. Поиск и автообновление работают с выбранным файлом.
- Чтение публичной записи обновления и каталога профилей допускает замену файлов писателем, чтобы просмотр не мешал обновлению или управлению профилями.
- Ошибка открытия GitHub из «О программе» обрабатывается внутри окна.

## Что проверить

1. Открыть диагностику обычным пользователем: состояние службы/API и последнего обновления должно отображаться без UAC. Проверить обновление сводки и копирование.
2. Сохранить ZIP без галочки журналов: только `report.txt` и `README.txt`. С галочкой — дополнительно существующие текущий/предыдущий журналы. Проверить русский текст и маскирование; файл никуда сам не отправляется.
3. В «Журнале» переключить текущий файл и архивы, воспользоваться поиском и кнопкой «Папка». Пустой или отсутствующий архив должен объясняться сообщением.
4. При смене аккаунта старая диагностическая сводка закрывается; успешное подключение нового аккаунта должно отражаться после получения данных.

Проверки: полный RegressionChecks, отдельные проверки ZIP/маскирования/отмены/ошибки, работающего писателя состояния обновления и записи журнала из двух независимых процессов. Реальные параллельные RDP-сеансы остаются отдельным пунктом проверки.
