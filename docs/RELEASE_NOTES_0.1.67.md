# VPN Monitor 0.1.67

Сохранение и управление историей объединены в один релиз.

- История AWG, доступности и endpoint сохраняется между запусками: до 7 дней и 2000 событий на сервер и аккаунт.
- Архивы защищены DPAPI текущего пользователя Windows и разделены по адресу сервера и имени аккаунта. Чужие сеансы Windows с другим пользователем не используют этот архив. Пароли и VPN-профили в него не записываются.
- История загружается после успешного получения списка клиентов; записи недоступных клиентов отбрасываются. Первое наблюдение после запуска задаёт новое исходное состояние: изменения за время закрытого приложения не реконструируются.
- В окне истории появилась очистка выбранного клиента с подтверждением. Остальные клиенты сохраняются; следующая проверка создаёт новое исходное состояние.
- «Настройки → Проверки → Сохранять историю клиентов между запусками»: включено по умолчанию. Отключение и сохранение настроек удаляют сохранённые архивы текущего пользователя Windows, оставляя историю текущего сеанса в памяти.
- Изменение обычных настроек больше не очищает историю текущего подключения. Смена сервера или аккаунта переключает архив и закрывает открытые окна истории.

Автосохранение выполняется в фоне раз в 15 секунд при наличии изменений; при штатном выходе или обновлении — дополнительно перед закрытием. При аварийном завершении последние несохранённые события могут потеряться. Файлы записываются заменой целого защищённого архива; отложенная запись не возвращает уже очищенные события. Повреждённый архив не мешает работе клиента.

Хранение: `%LOCALAPPDATA%\VpnMonitorClient\history`. Не более 20 архивов аккаунтов, каждый до 4 МБ; старые архивы и оставшиеся после аварии временные файлы очищаются при сохранении. История не переносится импортом/экспортом настроек. Параллельные экземпляры одного и того же пользователя Windows используют один архив подключения: сохраняется последний записанный снимок, объединения событий между процессами нет.

Проверить:
1. Открыть историю клиента, полностью выйти через меню трея и запустить приложение: старые записи должны остаться после подключения к серверу.
2. Очистить историю одного клиента; у остальных она должна остаться. После перезапуска очищенные старые события не должны вернуться.
3. Изменить обычную настройку: история должна сохраниться. При смене аккаунта история другого аккаунта не должна появляться.
4. При необходимости отключить сохранение в разделе «Проверки». Это удалит ранее сохранённую историю данного пользователя Windows.

Полный RegressionChecks пройден, включая реальные операции DPAPI, перезагрузку архива, ограничение доступа и объёма, срок хранения, повреждение файла и защиту от отложенных старых записей. Проверка с несколькими реальными RDP-сеансами остаётся отдельным пунктом.
