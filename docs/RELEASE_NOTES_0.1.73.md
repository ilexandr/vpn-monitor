# VPN Monitor 0.1.73

## Исправление потери связи после обновления

На одном компьютере после обновления служба была Running, но новый UDP-транспорт выбирал маршрут другого активного VPN. Handshake отсутствовал, принятых данных не было. Маршрут к Endpoint через физическую сеть восстановил связь без остановки других VPN.

- Движок создаёт временные адресные маршруты IPv4 к Endpoint через физическое подключение, учитывая метрику интерфейса и шлюза. Остальные маршруты и чужие явные адресные маршруты не заменяются. Собственные маршруты поддерживаются при смене сети и удаляются при остановке службы. Обход других VPN можно отключить в настройках профиля.
- После обновления проверяется реальная связь через новый процесс службы; одного Running больше недостаточно. При отсутствии подтверждения выполняются ограниченные повторные запуски и записывается ошибка восстановления.

## Автовосстановление и резервный Endpoint

- Один контроллер внутри общей службы AWG для всех Windows/RDP-сеансов. Он продолжает работать при закрытом клиенте и не запрашивает повышение прав у обычных пользователей.
- Проверки контрольного адреса внутри VPN: TCP, ICMP с исходным адресом туннеля, поступление входящего трафика и новое рукопожатие. Периодическое старое значение handshake не считается постоянным доказательством связи.
- После подтверждённого сбоя движок переподключается и восстанавливает адреса/маршруты своего интерфейса. При настроенном резервном Endpoint переключается между основным и резервным, сохраняя ключи и маршруты профиля.
- В менеджере — «Связь и резерв…» для выбранного профиля при отключённом туннеле. Настройки хранятся отдельно для каждого профиля в защищённом общем каталоге. Основной Endpoint берётся из профиля; резервный поддерживается для профилей с одним Peer.
- Настраиваются контрольный IPv4 и порт, интервал проверки, задержка подтверждения сбоя, пауза между попытками, возврат к основному и период такого возврата. Возврат предполагает короткое пробное переподключение и по умолчанию выключен.
- По умолчанию: проверка раз в 10 с, подтверждение 30 с, пауза 60 с; не более 3 переподключений за 10 минут. После старта предусмотрено время установления связи. Ручная остановка службы не вызывает её автоматический запуск.
- Если контрольный адрес не задан, используется подходящий адрес .1 из частного IPv4-маршрута профиля. Для других топологий нужно указать контрольный адрес явно. Состояние доступно в окне AWG; журнал контроллера ограничен по размеру.

## Интерфейс

- «Закрыть» и «Отмена» расположены справа, включая подтверждения, настройки и редактор действий. Кнопка отмены остаётся безопасным выбором по умолчанию. В узком менеджере AWG закрытие вынесено отдельно от переносимых кнопок команд.
- Меню трея теперь использует тот же WPF-шаблон, цвета, разделители и элементы меню, что остальные меню приложения; сохранены открытие, обновление, интерфейсы, настройки и выход.

## Что проверить

1. На остальных компьютерах обновиться обычным способом и убедиться, что восстановилась связь, а не только служба.
2. В менеджере AWG отключить туннель, открыть «Связь и резерв…» и проверить параметры выбранного профиля; после подключения посмотреть состояние в окне AWG.
3. Проверить отмену подтверждений, расположение кнопок и меню трея в светлой/тёмной теме и RDP.

Переименование и частичные обновления остаются в плане.
