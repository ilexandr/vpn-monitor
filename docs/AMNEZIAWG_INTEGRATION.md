## Архитектура (предложение)
WPF GUI → IPC с ограничением доступа → отдельный процесс службы → tunnel.dll / Wintun.
Установка службы требует повышения прав; GUI не должен постоянно работать от администратора.
Хранилище конфигураций и IPC ограничить ACL. DPAPI должен соответствовать контексту службы.

## Подтверждённые детали
WireGuardTunnelService принимает два указателя UTF-16: текст конфигурации и имя туннеля. Первый аргумент — не путь файла. Вызов запускает службу; не вызывать его из потока GUI. Точный ABI проверить по заголовку конкретной сборки, который штатный build.cmd удаляет.
README библиотеки указывает MIT; лицензии зависимостей проверить отдельно.
go.mod требует Go 1.25.0, тогда как build.cmd скачивает Go 1.24.4. До сборки согласовать toolchain и закрепить commit/SHA256. Go в локальном PATH не обнаружен.

Обнаружена работающая служба AmneziaWGTunnel$AdminLexWorkPC. Профиль и ключи не читались; служба не изменялась.

## Следующие этапы
1. Предпросмотр .conf без изменения сети: адреса, endpoint и маршруты; ключи скрыты. Не исполнять PreUp/PostUp/PreDown/PostDown. Не удалять молча неизвестные AWG-параметры.
2. Отдельный служебный прототип x64 с уникальным именем, доверенными абсолютными путями DLL и ограниченным IPC. Сборка из зафиксированных исходников.
3. Испытание в VM с отдельным тестовым peer: старт/стоп, DNS, маршруты, сон, потеря сети, восстановление и откат. Проверять конфликт маршрутов с рабочим туннелем.
4. Встраивание в UI после испытаний. Running службы, handshake и достижимость показывать отдельно. Ключи не писать в журнал и обычный экспорт настроек.

Сборка DLL, драйвер, совместимость с реальным профилем и живое подключение ещё не проверены. Следующий практический этап — безопасный предпросмотр конфигурации. Изменение рабочего туннеля согласовать отдельно.
