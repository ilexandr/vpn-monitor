# Управление пользователями Web — проверка 26.10.2026

## Реализация

Admin-only GET/POST/PATCH/DELETE `/api/v1/admin/users`, безопасные DTO без хешей, CSRF для записи, no-store, ограничение JSON и строгие типы полей. Admin из env защищён; обычные аккаунты имеют только прежнюю область своей группы. Настоящие группы/peers не создаются и не удаляются при CRUD аккаунтов.

Форма создания/редактирования, смена пароля и блокировка, подтверждение удаления, список групп и предупреждение об отсутствующей группе. Значения выводятся через textContent. Ошибки файловой системы обезличены. Сетевые операции интерфейса ограничены 15 секундами; пароли не сохраняются в localStorage.

Хранилище перенесено в `/var/lib/vpn-monitor/users/users.json`; старый путь сохранён ссылкой. Код, env, прежняя база, CLI и backup-скрипт предварительно сохранены в отдельном каталоге root с режимом 0700. Права веб-службы не повышались; ProtectSystem=full и отдельный пользователь сохранены. Перезапускался только веб-мониторинг.

## Локально

- `test_users.py`: 11 успешных проверок (включая базовую изоляцию доступа): CRUD, авторизация и CSRF, защищённый admin, дубликаты/валидация, сохранность прежнего пароля/данных, обезличенный отказ записи и конкурентные экземпляры UserStore.
- Проверки синтаксиса app.js/users.js и настоящий многословный поиск Web — PASS.
- Headless Edge: обе темы, форма и таблица проверены на локальных демонстрационных данных. Снимки не содержат реальных аккаунтов.

## На рабочем сервере

- Хеши семи установленных файлов совпали с локальными финальными исходниками.
- Настоящий API: создание временного аккаунта, вход и пустая область без группы, смена пароля (старый сразу отклоняется), блокировка (401), включение, удаление.
- Обычный аккаунт получает 403 для всех четырёх методов управления; без CSRF запись отклоняется. Удаление master-admin отклоняется.
- Временные аккаунты удалены; сравнение JSON до/после подтвердило сохранность существующих аккаунтов и хешей.
- Два настоящих процесса (root CLI и пользователь службы) параллельно создали 16 записей во временной базе без потерь. Эта отдельная база удалена после проверки.
- API мониторинга healthy, обновление WGDashboard работает, веб-служба active.
- Штатный backup дополнен настоящей базой, прежней ссылкой и CLI; архивация берёт общий shared-lock. Запуск backup завершился Result=success / ExecMainStatus=0, в том числе после финального обновления кода.

Полная процедура восстановления из архива не запускалась. Windows-интерфейс управления пользователями пока не менялся; API описан в Server/README.md.
