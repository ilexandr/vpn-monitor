# Характеристики устройств и диагностика — план, 04.11.2026

Запрос пользователя: карточка VPN-клиента с характеристиками ПК из базы сервера и возможностью обновления. Приложение AWG Dash Monitor установлено лишь на части ПК, остальные работают через нативный AWG. Этот документ — согласованное направление и предлагаемая архитектура; сбор данных ещё не реализован.

## Предлагаемая архитектура

Сервер хранит последнюю подтверждённую карточку устройства. Windows-программа и веб читают одну базу; наличие основного интерфейса мониторинга на самом ПК не требуется. Каждая запись содержит время измерения, время получения сервером, источник, версию сборщика, полноту данных и последнюю ошибку. Офлайн-ПК показывается с последними известными данными и отметкой устаревания; отсутствие данных не превращается в нулевой объём или «исправен».

1. На ПК с нашим приложением — встроенный сборщик, который отправляет сведения только о своём устройстве.
2. Для нативного AWG — небольшой отдельный сборщик/служба без основного интерфейса. Он сам устанавливает исходящее HTTPS-соединение с API через VPN, передаёт сведения и забирает разрешённые задания обновления. Новые входящие порты не нужны; Windows/RDP-сеансы не запускают несколько одинаковых сборов.
3. Для машин без сборщика возможен дополнительный режим WinRM/CIM или SSH, только после явной настройки доступа. Он не считается доступным по умолчанию и не использует общий root/admin-пароль для всех ПК. Секреты хранятся отдельно от инвентарной базы. SMB, RDP и handshake AWG сами по себе не предоставляют характеристики оборудования.

Предпочтителен гибрид первого и второго варианта. Факт нового handshake — не надёжное событие загрузки/входа: повторные handshake не должны запускать дорогое сканирование. На устройствах без приложения, агента или настроенного удалённого доступа будет честное состояние «Источник данных не настроен».

## Какие данные

- Материнская плата: производитель и модель; версия/дата BIOS/UEFI, если источник предоставляет их.
- CPU: модель, сокеты, ядра и потоки; архитектура.
- RAM: установленный и доступный объём; модули/слоты/частота, если доступны без повышенных прав.
- Физические накопители: модель, объём, шина и тип носителя. HDD/SSD/NVMe определять по данным ОС/Storage API; NVMe — тип подключения, SSD — тип носителя. RAID, виртуальные и неизвестные устройства отмечать явно, не угадывать по имени.
- Логические тома: буква/точка монтирования, файловая система, общий и свободный объём, процент свободного места; сопоставление с физическим диском, если надёжно известно.
- ОС: редакция/версия/сборка, архитектура, время последней загрузки и uptime, наличие ожидающей перезагрузки, версия AWG/сборщика.
- Базовая диагностика: нехватка места, доступная память, состояние службы туннеля и последние ошибки сбора. При необходимости — состояние важных служб и дата последних обновлений ОС.
- SMART/температуры/ресурс SSD, износ NVMe, состояние защиты и подробная диагностика — отдельный opt-in: данные зависят от прав и драйверов и не всегда доступны.

Серийные номера, MAC, имена пользователей, список ПО/процессов и журналы событий по умолчанию не собирать: для них требуется отдельное обоснование и настройка. Не передавать VPN-ключи, пароли и содержимое пользовательских файлов.

## Обновление и интерфейс

Предлагаемые начальные интервалы (уточнить при реализации): полный снимок оборудования при первом запуске, затем не чаще раза в сутки и после изменения конфигурации; свободное место/доступная память/uptime — раз в 15–60 минут с разбросом времени и общим бюджетом сервера. После восстановления связи отправлять просроченные данные, а не запускать полный сбор на каждом handshake.

В карточке клиента: вкладка «Устройство», краткая сводка CPU/RAM/ОС, таблица дисков и томов, последние обновление/источник/ошибка. Кнопка «Обновить данные» создаёт серверное задание для привязанного сборщика; отображаются очередь, выполнение, результат и таймаут. Для офлайн-ПК задание ожидает подключения с ограниченным сроком жизни. При отсутствии источника кнопка объясняет, что нужно настроить. Ручной запрос ограничивается по частоте и не обходит права группы.

## Привязка и права

Привязывать устройство к стабильному ID VPN-peer/серверу, а не только к текущему IP или имени. Нужна явная регистрация устройства с отзывным отдельным токеном и серверным сопоставлением с peer; один общий admin-пароль в сборщики не встраивается. Администратор видит разрешённые устройства, обычный пользователь — только свою группу, одинаково в веб и Windows. Устройство может записывать только собственную карточку. Проверять схему, размер, время и частоту запросов; не доверять присланному устройством чужому peer ID. Настройки и база совместимы с несколькими Windows/RDP-сеансами.

## Этапы и проверки

1. Схема данных и API, регистрация/отзыв устройства, ограничения доступа и миграция базы.
2. Windows-сборщик с проверкой на обычных правах, неизвестных дисках/RAID/VM, частичных ошибках и ограничением времени каждого запроса ОС.
3. Карточка из серверной базы в веб/Windows и очередь ручного обновления.
4. Маленький установщик отдельной службы для ПК с нативным AWG; затем опциональные SSH/WinRM и расширенная диагностика.

Проверить повторное подключение без лавины запросов, разрыв связи во время сбора, офлайн-очередь/таймаут/отзыв токена, переход между группами, отсутствие утечек между аккаунтами, ограниченный размер/хранение истории и удаление устройства. Для MVP хранить один последний снимок и ограниченный журнал заданий; долговременную историю изменений добавлять отдельно.
