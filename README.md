# AWG Dash Monitor

Windows-клиент для мониторинга клиентов WGDashboard / AmneziaWG через серверный API, с Web-интерфейсом и управлением общим AWG-туннелем. Ранее — VPN Monitor.

## Компоненты

- VpnMonitor.Client — WPF-клиент .NET 8 для Windows.
- Server — FastAPI-сервер, авторизация, Web-интерфейс.
- AwgPrototype/Host — служебный процесс общего туннеля.
- AwgPrototype/Manager — панель администратора для профилей и управления.
- RegressionChecks — локальные проверки.
- docs — технические планы.

Текущая версия клиента: 0.1.75. Доступны установщик Windows x64 и обновление из окна «О программе» через GitHub Releases с проверкой SHA-256, запросом UAC и восстановлением ранее работавших приложений и общего туннеля.

## Сборка

Требуется Windows и .NET 8 SDK.

    dotnet build VpnMonitor.Client -c Release
    dotnet run --project RegressionChecks -c Release -- --actions-only
    dotnet run --project RegressionChecks -c Release -- --access-only

Проверки не требуют рабочего VPN-профиля. Наличие локального TEST.conf добавляет проверку структуры без вывода ключей; этот файл не публикуется.

## Сервер

Настройка описана в Server/README.md. Реальные переменные окружения, база пользователей и ключи WGDashboard не входят в репозиторий.

## Общий туннель Windows

Профили и служба общие для компьютера; личные настройки и API-пароль относятся к профилю пользователя Windows. Управление выполняется панелью администратора. Отключение общего туннеля затрагивает все сеансы.

Внешний движок не включён как вложенный Git-репозиторий. AwgPrototype/Prepare-Engine.ps1 получает закреплённый commit upstream и добавляет локальный файл экспортов. Затем подготовьте проверенные инструменты Go/MinGW и Wintun согласно документации прототипа.

Работа с несколькими RDP-сеансами проверена пользователем. Начиная с 0.1.73 служба контролирует поступление трафика собственного туннеля, восстанавливает соединение и при необходимости переключает Endpoint на резервный. Настройки общие для компьютера.

## Публикация

VPN-профили, секреты, персональные настройки, логи, отчёты и скачанные инструменты сборки не включаются в репозиторий. Лицензии сторонних компонентов сохраняются; условия лицензирования собственного кода пока не выбраны.

В 0.1.63 общий туннель проверяется каждые 10 секунд, пока работает приложение (включая трей): TCP к адресу и порту сервера из настроек, таймаут 3 секунды. После трёх неудач показывается предупреждение, при восстановлении — уведомление. Проверка работает независимо от проверок клиентов. Доступность сервера не доказывает исправность всех маршрутов VPN; сбой сервера также вызывает предупреждение. Начиная с 0.1.73 внутри службы отдельно работает контроль собственного трафика с автоматическим переподключением; ручная остановка не отменяется.


Начиная с 0.1.62 доступно «О программе»: ручная проверка стабильных GitHub Releases, изменения версии и кнопка «Обновить». Версия 0.1.62 уже умеет обновляться через GitHub Releases; более ранние версии нужно сначала обновить установщиком.

Автономное обновление требует UAC. Помощник повторно получает релиз из закреплённого репозитория и проверяет SHA-256 GitHub release asset до остановки сети. Затем экземпляры клиента и менеджера завершаются через защищённый IPC; их помощники остаются в исходных пользовательских сеансах и восстанавливают программы после завершения. Останавливается и восстанавливается только общий туннель VpnMonitor.AwgPrototype, если он работал перед установкой. Посторонние VPN-службы не изменяются. Установщик запускается тихо, без перезагрузки Windows. При ошибке установки восстанавливаются резервные копии двоичных компонентов; предпринимается восстановление туннеля и закрытых приложений.

Журналы и резервные копии обновлений: ProgramData/VpnMonitor/Updates (администраторы и SYSTEM). Публичные файлы состояния не содержат ключей и паролей. Данные профилей и настройки пользователей в резервные копии двоичных компонентов не входят и установкой не заменяются. Для проверки обновлений нужен опубликованный стабильный релиз с именем VpnMonitor-Setup-X.Y.Z-win-x64.exe и SHA-256 digest в GitHub API. Формат: https://docs.github.com/en/rest/releases/releases.


0.1.63 — первый опубликованный релиз: обновление из 0.1.62 через GitHub Releases. При установке сохраняется тип запуска существующей службы, после тихой установки дополнительно проверяется установленная версия.


0.1.64: неизвестные счётчики при потере связи, автоматическая подготовка удаления, повторные попытки восстановления службы с диагностикой. См. docs/RELEASE_NOTES_0.1.64.md. Частичные обновления запланированы в VpnMonitor.Client/ROADMAP.md.

0.1.66: поиск истории клиента по всем словам, экспорт видимой истории в CSV UTF-8, время последней проверки и успешной связи в окне AWG. История по-прежнему хранится только в текущем сеансе (до 2000 событий). Обновлён план с учётом готовых функций.

0.1.67: история клиентов сохраняется между запусками на 7 дней (до 2000 событий на сервер и аккаунт), защищается DPAPI текущего пользователя Windows. Загрузка — после успешной авторизации с фильтрацией разрешённых клиентов. Очистка отдельного клиента — в окне истории; отключение сохранения — «Настройки → Проверки». Сохранённые архивы не входят в экспорт настроек.

0.1.68: «О программе → Диагностика и отчёт» — сводка API/AWG/последнего обновления и локальный ZIP-отчёт. Журналы добавляются отдельно по выбору, типовые секреты и известный пароль маскируются. Ротация журнала: текущий файл + три архива по 2 МБ; выбор архивов, открытие папки и переход к диагностике доступны в просмотрщике. См. docs/RELEASE_NOTES_0.1.68.md.

0.1.69: возврат фокуса после закрытия дочерних окон, устойчивость к краткому сбросу HTTP, диагностика ошибок и восстановления, тестовое уведомление Windows. Настройки сохраняются атомарно с предыдущей исправной копией; проверки полностью отделены от рабочего клиента, его настроек и журнала. См. docs/RELEASE_NOTES_0.1.69.md.


## Версия 0.1.74

В менеджере доступна «Конфигурация…»: полный текст профиля с масками существующих ключей. Сохранение — только при остановленной службе, после проверки движком и проверки политики восстановления. Секреты передаются внутри процесса; в файле хранится только DPAPI. Если профиль изменился в другом сеансе, устаревшее сохранение отклоняется.

Сводка выбранного профиля показывает основной/резервный Endpoint, ответ ICMP резервного узла раз в 30 секунд и подтверждение работы резервного AWG по состоянию службы. Ответ ping не доказывает исправность UDP-порта AWG; пассивная проверка не переключает туннель.

Новое отображаемое имя — AWG Dash Monitor. Адрес репозитория/обновлений, AppId, имена exe и службы, DPAPI и каталоги данных сохранены для совместимости. Ярлыки меню «Пуск» обновляются установщиком. Подробности: docs/RENAME_COMPATIBILITY.md.

Для будущих частичных обновлений сборка создаёт `file-manifest.json` (размеры и SHA-256). `Installer/Get-UpdateFilePlan.ps1 -Manifest <path> -InstallRoot <path>` только рассчитывает отличия. Текущий клиент продолжает загружать полный установщик; загрузка отдельных файлов, доверие к манифесту и транзакционное применение с откатом — следующий этап.


## Версия 0.1.75

«История связи…» в менеджере сохраняет 200 событий службы. «Проверить резерв…» временно переключает общий туннель с исправного основного на резерв, проверяет входящий трафик и возвращает основной. Команду выполняет служба; закрытие менеджера не мешает возврату, ручное отключение останавливает туннель. Проверка требует подтверждения и свободного бюджета попыток, не меняет профиль.

«О программе → Проверить обновления → Состав версии…» загружает проверенный по SHA-256/версии/commit манифест GitHub и сравнивает файлы с установленной версией. Доступно и для текущего релиза. Размеры показаны без сжатия; установка пока полным пакетом. См. docs/RELEASE_NOTES_0.1.75.md и docs/RELEASE_VERIFICATION_0.1.75.md.
